# FACEIT Match Bot

Бот получает статистику завершённых CS2-матчей через FACEIT Data API,
дополняет её Rating/Swing через FlareSolverr и отправляет сводки в Telegram.
Один запуск выполняет один опрос и завершается; регулярные проверки выполняет cron.

## Как работает бот

### Обнаружение матчей и первое сообщение

Один запуск читает историю каждого игрока до его сохранённого match ID,
с пагинацией, и обрабатывает все новые завершённые матчи. Общие матчи игроков
объединяются в одно сообщение. Отправка идёт от ранних матчей к поздним. После получения основной статистики бот делает
запрос Rating/Swing и отправляет результат в этом же запуске. Если основная
статистика недоступна, отправка откладывается до следующего запуска.

Временной задержки после завершения матча нет. Скорость обнаружения зависит
от cron: при расписании раз в 15 минут матч будет замечен на ближайшей проверке.
Сетевые запросы и их таймауты могут увеличить длительность запуска.

При `NOTIFY_ON_FIRST_RUN=false` (по умолчанию) первый запуск запоминает последний
матч каждого игрока без уведомления. Это же правило действует для нового игрока,
добавленного в `players.json`. При `NOTIFY_ON_FIRST_RUN=true` последний матч
отправляется и при первом наблюдении. Если матчей ещё нет, первый будущий матч
будет обработан обычным образом.

После простоя бот восстанавливает все матчи после сохранённой точки. Если точка
не найдена или история не загрузилась полностью, новые уведомления откладываются,
а состояние сохраняется. Ошибка отправки останавливает очередь до следующего
запуска, чтобы поздний матч не обогнал ранний.

Успешные отправки записываются также в `__sent_matches__` внутри state. При
повторном обходе уже отправленный матч пропускается. Для намеренного повторного
отправления оператор отдельно сохраняет backup, возвращает player cursors к
исходной границе и очищает receipts только для выбранных матчей.

Для воспроизведения зафиксированного списка можно выполнить
`./deploy/run.sh --replay-plan <audit-snapshot.json>`: snapshot содержит объект
`players`, у каждого игрока `matches` со списком объектов `match_id`. Перед
отправкой история сверяется с этим списком; игры вне snapshot не включаются.
Обычный cron затем продолжит с сохранённой точки.

### Ожидание Rating и Swing

Данные берутся из scoreboard-summary сайта FACEIT через FlareSolverr. Наличие
обоих числовых полей у игрока означает готовность; нулевой Swing тоже готов.
Swing переводится в проценты: например, `0.0187` отображается как `+1.87%`.

Если данные доступны сразу, они входят в первое сообщение. Иначе в строке
соответствующего игрока ячейки Rating и Swing объединяются и содержат пометку
`⏳ Rating и Swing рассчитываются`. Остальная статистика выводится сразу.

Пометка означает, что бот пока не получил показатели. Причиной может быть
незавершённый расчёт FACEIT, недоступность FlareSolverr или ошибка запроса.

После успешной отправки бот сохраняет в `last_matches.json` очередь обновлений:
ID матча, Telegram message ID, чат, время отправки, исходную статистику, список
игроков и уже полученные показатели. На последующих запусках cron бот проверяет
эти матчи независимо от новых матчей игроков.

Когда данные появляются, бот [редактирует исходное сообщение](https://core.telegram.org/bots/api#editmessagetext).
Отдельное сообщение с дополнением не отправляется. При частичном ответе готовые
Rating/Swing добавляются сразу, а у остальных участников сохраняется пометка
ожидания. Уже полученные данные не теряются, если следующий ответ пустой.
Если текст не изменился, запрос редактирования в Telegram не выполняется.

### Срок ожидания и ошибки

Для каждого сообщения окно получения показателей составляет **четыре часа с момента
его успешной отправки**. Оно не продлевается при перезапуске бота или частичном
обновлении. Проверки выполняются при запусках cron; отдельного фонового процесса
ожидания нет.

На первом запуске в момент истечения срока или позднее бот прекращает запросы
Rating/Swing для этого сообщения. У игроков с недостающими показателями пометка
меняется на `Rating и Swing недоступны`. Готовые показатели сохраняются.

Например, при отправке в 18:00 и cron раз в 15 минут повторные проверки возможны
в 18:15, 18:30 и далее до 21:45. Если в 18:30 данные появились у всех игроков,
сообщение обновляется и удаляется из очереди. Если часть данных не появилась,
на запуске в 22:00 ожидание завершается. После простоя VPS завершение произойдёт
на первом следующем запуске.

Ошибка Telegram при редактировании не удаляет задание: бот сохранит данные и
повторит редактирование на следующем запуске. Это касается и финальной пометки
о недоступности после четырёх часов; повторные запросы Rating после срока уже
не выполняются. Бот не пересоздаёт удалённые сообщения. Если исходное сообщение
удалено или редактирование запрещено, попытки редактирования будут завершаться
ошибкой, а задание останется в очереди.

При ошибке FlareSolverr или HTTP 200 с невалидным JSON запрос повторяется один
раз через 5 секунд. Успешные Rating/Swing сохраняются в `faceit_ratings.json`
рядом с state (mode `600`). При повторной отправке или временном сбое уже
полученные показатели используются из кэша и не заменяются ожиданием.
Ответ HTTP 200 сам по себе не означает успешное получение статистики: FACEIT
может вернуть JSON с `errors`. Бот записывает код ошибки и ID матча в лог,
а ранее полученные показатели сохраняет. В частности, `err_f0` с текстом
`this content is not available for anonymous users` означает, что для этой
статистики требуется вход в FACEIT. FlareSolverr сам по себе не авторизует
аккаунт; увеличение срока ожидания не устраняет ограничение доступа.
Такая ошибка не считается подтверждением того, что показатели ещё рассчитываются,
и не вызывает немедленного сетевого повтора. Авторизация FACEIT в текущей
версии бота не настроена автоматически.

Если данные не получены, первое уведомление всё равно отправляется, а дальнейшие
проверки выполняются по cron в пределах четырёхчасового окна. При
`FLARESOLVERR_ENABLED=false` в новых сообщениях вместо значений Rating/Swing
стоят прочерки, без пометок
ожидания и не добавляются в очередь. Для уже ожидающих сообщений сохраняется
срок окончания; новые показатели при отключённом FlareSolverr не запрашиваются.

Срок четыре часа и задержка сетевого повтора пять секунд заданы в `bot.py`;
отдельных переменных окружения для них нет.

### Вид сообщения и порядок игроков

Сообщение содержит заголовок с картой и счётом, время и общий результат матча,
затем одну широкую таблицу. Все показатели игрока расположены в одной строке.

**🎮 Dust2 · 13:3**

⏱ 14:36–15:02 · 25м 11с

🏁 Результат: 🟢 **ПОБЕДА** 🎉

| Игрок | Rating | Swing | K/D | K/D Ratio | ADR | MVP |
|---|---|---|---|---|---|---|
| Nickname1 | 🟢 1.55 | 💚 +7.24% | 20/10 | 2.00 | 95.0 | 3 |
| Nickname2 | ⚪ 1.07 | 🔻 -0.71% | 11/7 | 1.57 | 70.5 | 2 |

🔗 Открыть scoreboard

`K/D` содержит количество убийств и смертей, `K/D Ratio` — их отношение.
Таблица имеет границы, чередование фона строк и компактные отступы.
Все показатели видны сразу, без раскрываемых блоков. Новые сообщения и
обновления Rating/Swing всегда используют один и тот же однострочный формат;
чередования форматов нет.

Используется [Telegram Rich Messages](https://core.telegram.org/bots/api#sendrichmessage)
с Rich HTML, а не обычный `parse_mode=HTML` или `MarkdownV2`.
Для корректного отображения используйте актуальное приложение Telegram.
Обновление показателей редактирует это же сообщение и пересортировывает игроков
целиком в этой же таблице, без нового сообщения.

Ссылка ведёт на вкладку `/scoreboard` комнаты. Время отображается в часовом
поясе `APP_TIMEZONE`.

Цветной индикатор перед Rating обозначает уровень показателя:

| Rating в сообщении | Индикатор | Уровень |
|---|---|---|
| от 1.80 | 🟠 | очень высокий |
| 1.30–1.79 | 🟢 | высокий |
| 1.00–1.29 | ⚪ | средний |
| 0.99 и ниже | 🔴 | низкий |

Индикатор выбирается по значению, округлённому до двух знаков, как в сообщении:
например, `1.799` отображается как `🟠 1.80`. Правило применяется и при
первой отправке, и при дополнении сообщения. Если Rating отсутствует, цветной
индикатор не показывается. Значки Swing (`💚` и `🔻`) зависят только от знака Swing.

Игроки сортируются по убыванию числового значения: FACEIT Rating, если он есть,
иначе K/D этого игрока. При частичных данных эти значения сравниваются между
собой; если Rating нет ни у кого, используется только K/D. При равенстве
сохраняется порядок из `players.json`. После дополнения данных порядок
пересчитывается.

Победа или поражение выводится один раз и определяется по первому игроку из
`players.json`, найденному в статистике матча. Сортировка строк на результат
не влияет. Общий результат рассчитан на игроков одной команды: если отслеживаемые
участники попали в разные команды, он относится к первому из них.

### Сессии и одновременные запуски

Браузерные сессии FlareSolverr удаляются в конце запуска. Перед созданием сессии
бот очищает оставшиеся сессии с префиксом `faceit-bot-`; сессии других приложений
с другими именами не затрагиваются. Если проверить или очистить свои сессии
не удалось, новая сессия не создаётся.

Запуски с одним файлом состояния защищены файловой блокировкой: второй процесс
завершается с записью `Another bot run is active; skipping this check.`.
Если нет новых матчей и очереди обновлений, FlareSolverr не опрашивается, а в
журнале остаётся `No new matches found.`.

## Развёртывание через GitHub

Для штатных deployment-скриптов используется Linux и checkout `~/faceit_bot`.
Запускайте их от владельца checkout: env и state берутся из его `$HOME`,
а cron использует фактический абсолютный путь checkout. Нужны Git, Python 3.10+ с `venv`, Bash,
`flock`, cron и исходящий HTTPS. FlareSolverr нужен для Rating/Swing;
без него можно установить `FLARESOLVERR_ENABLED=false`.

Создайте отдельный ED25519 deploy key на VPS и добавьте публичный ключ в Settings →
Deploy keys этого репозитория с доступом только на чтение. Закрытый ключ сохраняйте
на VPS с mode `600`; проверьте официальный SSH host fingerprint GitHub.

```bash
GIT_SSH_COMMAND="ssh -i $HOME/.ssh/faceit_bot_deploy -o IdentitiesOnly=yes" \
  git clone --branch main git@github.com:KempeR1t/faceit-telegram-match-bot.git ~/faceit_bot
cd ~/faceit_bot
git config core.sshCommand "ssh -i $HOME/.ssh/faceit_bot_deploy -o IdentitiesOnly=yes"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
install -d -m 700 ~/.config ~/.local/state/faceit_bot
touch ~/.config/faceit_bot.env
chmod 600 ~/.config/faceit_bot.env
```

Заполните `~/.config/faceit_bot.env` по `.env.example`:

- `FACEIT_API_KEY` — server-side ключ из FACEIT Developer Portal;
- `TELEGRAM_BOT_TOKEN` — токен BotFather, можно сначала оставить пустым;
- `TELEGRAM_CHAT_ID` — целевой чат; бот должен иметь право отправлять в него;
- `FACEIT_PLAYERS_FILE=/home/kemper1t/faceit_bot/data/players.json`;
- `STATE_FILE=/home/kemper1t/faceit_bot/data/last_matches.json`;
- `APP_TIMEZONE=Europe/Moscow`, `FACEIT_GAME=cs2`;
- `TELEGRAM_PROXY_URL=` для прямого подключения;
- `FLARESOLVERR_ENABLED=true`, `FLARESOLVERR_URL=http://127.0.0.1:8191/v1`.

Создайте `data/` с mode `700`, список игроков и исходный файл состояния с mode
`600`. Данные и env исключены из Git. Секреты не вводите в команды с литералами,
не публикуйте в Git и не отправляйте в чат.

```bash
./deploy/validate.sh
./deploy/install-cron.sh
```

Устанавливается один managed cron block: `*/10 * * * *`, owner — текущий пользователь.
Runner и updater используют общий эксклюзивный `flock`; повторный опрос пропускается,
обновление при активном опросе отказывается менять код. При пустом Telegram-токене
cron пропускает выполнение, сохраняя baseline и success marker.

## Ввод Telegram-токена

Подключитесь к VPS и выполните:

```bash
~/faceit_bot/.venv/bin/python ~/faceit_bot/deploy/set-telegram-token.py
```

Проверка токена использует `TELEGRAM_PROXY_URL` из env. Для SSH SOCKS-туннеля
укажите `socks5h://127.0.0.1:1080`: DNS Telegram разрешается на удалённом VPS.
Туннель должен работать постоянно, слушать только loopback и проверять SSH host key.

Скрипт запрашивает токен скрытым вводом, проверяет `getMe` и доступность настроенного
чата через `getChat`, затем атомарно сохраняет значение в
`~/.config/faceit_bot.env` с mode `600`. Сообщений для проверки не отправляет.
Следующий cron запуск обработает все новые матчи относительно сохранённого baseline.
Для запуска сразу после ввода токена: `~/faceit_bot/deploy/run.sh`.

## Файл состояния

`last_matches.json` содержит последний обработанный match ID для каждого
игрока и служебный раздел `__pending_messages__` с очередью обновлений.
Файл создаётся автоматически, записывается атомарно и исключён из Git.
Существующий файл старого формата читается автоматически; удалять его не нужно.
Сохранённые сообщения обновляются с исходными игроками, часовым поясом и чатом.

Рядом автоматически создаётся `last_matches.json.lock`: блокировка предотвращает
пересечение запусков с одним файлом состояния и снимается при завершении процесса.
Пустой файл блокировки можно оставить на месте; переносить его не требуется.
Параллельные экземпляры бота с разными файлами состояния не должны использовать
один FlareSolverr: у них общий префикс браузерных сессий.

При отсутствии файла бот создаёт его при первом запуске с учётом
`NOTIFY_ON_FIRST_RUN`. Удаление состояния сбрасывает историю обработанных
матчей и очередь редактирования. Сохраняйте его при обновлении и переносе.

Бот может дополнять только сообщения, чей ID сохранён в очереди. В установках,
обновлённых с версий до 1.4.0, ранее отправленные сообщения автоматически
не дополняются: те версии не сохраняли Telegram message ID.

## Обновление и диагностика

GitHub `main` — источник кода. Файлы Python на VPS вручную не редактируйте.

```bash
cd ~/faceit_bot && ./deploy/update.sh
```

Updater проверяет чистоту checkout и ветку, применяет только fast-forward,
синхронизирует `.venv`, выполняет pip check, syntax checks и тесты. Запуск бота
и cron не меняет. Зависимости установки автоматически не откатываются при ошибке.

Read-only preview до первого запуска (не обращается к Telegram, не меняет state):

```bash
set -a
source ~/.config/faceit_bot.env
set +a
~/faceit_bot/.venv/bin/python ~/faceit_bot/deploy/preview.py
```

Логи — `~/.local/state/faceit_bot/logs/cron.log` с ограниченной ротацией;
health marker успешного опроса — `~/.local/state/faceit_bot/last-success`.
Пропуск из-за пустого токена или активной блокировки marker не обновляет.
Резервные копии crontab — `~/.config/deployment-backups/faceit-bot-crontabs/`.

Проверки разработки из checkout с установленными зависимостями:

```bash
python -m unittest discover -s tests -q
```
